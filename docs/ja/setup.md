# セットアップガイド(日本語) — 始める前に人間がやること

jupyter-rmcp を GCE の無料枠に立てて、Claude(スマホアプリ含む)からノートブックを
動かせるようにするための準備手順です。**アカウント作成・課金設定・ブラウザ認証など、
自動化できない部分だけ**をここにまとめています。

準備が終わったら、実際の構築は Claude Code に任せられます。手順書は
[docs/deploy/gce-cloudflare.md](../deploy/gce-cloudflare.md) にあり、Claude Code が
そのまま実行できる形で書かれています。

## これは何をするものか

Claude に「本物の Jupyter 環境」を渡す MCP サーバーです。コードを書くだけでなく、
実行して出力を見て直す、というループが回ります。ノートブックは `.ipynb` ファイルとして
残り、JupyterLab で自分でも開いて編集できます。

**計算は全部 Google Colab の GPU 上で走ります。** 手元(GCE の VM)では一切コードが
実行されません(`COLAB_ONLY` モード)。これは安全のためでもあり、無料枠の 1GB RAM で
成立させるためでもあります。Kaggle コンペで T4 を回す、という使い方が主な想定です。

## 必要なアカウントと費用

| 必要なもの | 費用 | 備考 |
|---|---|---|
| Google Cloud アカウント | 無料枠内なら基本 0 円。**クレジットカード登録は必須** | e2-micro 1台/月が always free |
| Colab が使える Google アカウント | 従量(compute units) | GPU を実際に使う分。Pro だと割り当てが取りやすい |
| Cloudflare アカウント | 無料(Zero Trust は 50 ユーザーまで無料) | |
| 独自ドメイン | 年 1,500 円程度 | **Cloudflare で管理しているドメインが必須**。Access が使えない |
| Kaggle アカウント | 無料 | API トークンを使う場合 |

**注意してほしい費用の話が 2 つあります。**

ひとつは**外部 IPv4 アドレスの課金**です。GCP は 2024年2月から VM に付く使用中の外部
IPv4 を課金対象にしていますが(時間 $0.005、月 $3.6 程度)、always free の e2-micro が
対象外かどうかは公式ドキュメントに明記がありません。**「無料枠だから 0 円のはず」と
思い込まないでください。** 手順書の Phase 1 で予算アラートを設定するので必ず実施し、
最初の請求書を一度確認してください。

もうひとつは**下り通信 1GB/月**の上限です。ノートブックの編集程度なら全く問題なく、
Kaggle のデータは Colab 側に落ちるので無関係ですが、JupyterLab をブラウザで何度も
開くと超える可能性があります。

## 準備 1 — Google Cloud

1. https://console.cloud.google.com でアカウント作成、請求先(クレカ)を登録
2. `gcloud` CLI をローカル PC にインストール
   ([インストール手順](https://cloud.google.com/sdk/docs/install))
3. `gcloud auth login` でログイン

プロジェクト作成と VM 作成は Claude Code がやるので、ここまでで OK です。

## 準備 2 — Colab 用の認証(ADC)

Colab をコマンドラインから動かすために、**あなたの Google アカウント**の認証情報が
必要です。VM のサービスアカウントでは Colab は使えません。

これは VM 上で対話的に実行する必要があり、手順書の Phase 3 に含まれています。ブラウザの
無い VM 上で実行するので、**URL が表示されるので手元のブラウザで開き、出てきたコードを
貼り戻す**、という流れになります。Claude Code はここで止まってあなたに聞いてきます。

コマンド自体は手順書にありますが、`colaboratory` スコープを含めるのが要点です。ここを
外すと、認証は通るのに `start_kernel` の段階で初めて失敗します。

## 準備 3 — Cloudflare

1. https://dash.cloudflare.com でアカウント作成
2. **ドメインを Cloudflare に追加**(既存ドメインのネームサーバーを Cloudflare に向けるか、
   Cloudflare Registrar で新規取得)
3. Zero Trust を有効化(左メニューの Zero Trust。チーム名を決める。無料プランで十分)

API トークンを作る場合(手順書の一部を API でやるとき)は、
My Profile → API Tokens → Create Token → Custom token で、以下の権限を付けます。

- **Account** → Access: Apps and Policies → **Edit**
- (リモートの Claude Code も使うなら)**Account** → Access: Service Tokens → **Edit**

アカウント ID は Cloudflare ダッシュボードの URL に含まれています。

## 準備 4 — Kaggle(使う場合)

kaggle.com → Settings → API → **Create New Token** で `kaggle.json` がダウンロード
されます。中身のトークン文字列を手順書の指示に従って `.env` に入れます。

このトークンは `setup_kaggle` で **Colab の VM 上に送られます**。つまり Colab で動く
コードから読める状態になります。これは仕様であり、Kaggle CLI を使うために必要ですが、
「そういう性質のものだ」と理解した上で使ってください。

## 準備 5 — Claude 側

- **Claude Code**(ローカル/リモート): 手順書の中で `claude mcp add` を実行します
- **Claude アプリ(スマホ・Web)**: 構築が終わったあと、Settings → コネクタ →
  カスタムコネクタを追加 → `https://mcp.あなたのドメイン/mcp` を登録します

## 守ってほしいこと

**会社のデータをここに置かないでください。** これは個人プロジェクト用の実行環境です。
Colab の VM 上には Kaggle や HuggingFace のトークンが置かれますし、実行されるコードは
サンドボックス化されていません。コンプライアンス上の要求があるデータの置き場所としては
不適切です。

**`COLAB_ONLY=1` を外さないでください。** 会社の PC や、自分の管理下にないマシンで
使う場合は特にそうです。これを外すと VM 上で任意のコードが実行できるようになります。

**Access の許可リストは自分のメールアドレス 1 つだけにしてください。** 「認証済みの
全ユーザー」やグループを指定すると、その範囲の全員があなたのコード実行環境に入れます。

**認証を設定し終わる前にトンネルを公開したまま放置しないでください。** 手順書の Phase 4
から 6 の間は、URL を知っている誰でもアクセスできる状態です。手順書にも警告がありますが、
途中で中断するときは先に `cloudflared` を止めてください。

## Claude Code への渡し方

準備が終わったら、リポジトリを clone して Claude Code にこう言えば始まります。

```
docs/deploy/gce-cloudflare.md の手順で GCE にデプロイして。
ブラウザ操作が必要なところで止めて指示して。
```

手順書には各フェーズの検証コマンドと、Claude がやってはいけないこと(無料枠を超える
リソースを作らない、秘密情報をコミットしない、許可リストを広げない)が明記してあります。

## うまくいかないとき

日本語での代表的な詰まりどころです。詳細な切り分けは手順書の "When it fails" にあります。

**mcp コンテナが再起動を繰り返す** — Colab の認証情報が読めていません。これは
`COLAB_ONLY` モードの意図的な動作で、「1 回ずつ失敗する」のではなく「起動を拒否する」
設計です。`docker compose logs mcp` にどちらが原因か出ます。`.env` の `GCLOUD_ADC` が
絶対パスになっているか、`MCP_UID`/`MCP_GID` が `id -u`/`id -g` と一致しているかを
確認してください(認証ファイルは 600 なので UID が合わないと読めません)。

**ビルドが謎のエラーで落ちる** — メモリ不足です。swap を先に作ったか(`free -h`)、
`-f compose.slim.yaml` を付けたかを確認してください。

**Claude Code からは繋がるのにスマホアプリから繋がらない** — ほぼ確実に
`WWW-Authenticate` ヘッダの問題です。手順書の Phase 6 の検証をやり直してください。
`curl -I` では分からないので `curl -D -` を使ってください。

**全部 302 になった** — Access アプリを誰かが再作成・編集して、ポリシーか OAuth 設定が
消えた可能性が高いです。Phase 6 をやり直してください。
